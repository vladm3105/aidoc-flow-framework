# PLUGIN-MARKETPLACE Plan — make the Claude Code plugin self-contained, validated & publishable

| Field      | Value                          |
|------------|--------------------------------|
| Task       | PLUGIN-MARKETPLACE             |
| Depends on | The plugin at `platforms/claude-code-plugin/`; the `sdd_doc_lint` vendoring precedent (`tools/sdd_doc_lint/sync-vendored.sh` + `tests/conformance/platforms/test_doc_lint_vendoring.py`); the claude-code-guide marketplace checklist; D-0013 (single-source-of-truth for templates) |
| Status     | PLANNED — 2026-05-27 |
| Feeds      | A self-contained, validated, documented Claude Code plugin that installs and runs from a marketplace; a path to a public storefront + open-core commercialization |

## Objective

Make `platforms/claude-code-plugin/` a **self-contained, validated, documented**
unit that actually works when Claude Code installs it from a marketplace — then
set up the publishing path. The monorepo stays the single source of truth; the
plugin ships everything it references.

> **Reality check (why this exists):** today the plugin references **47 distinct
> `framework/…` paths across 64 files**, but Claude Code copies **only the plugin
> dir** to its cache on install — so those references break for every installed
> user. The plugin is **not installable** and **not "tested"** beyond static
> checks. Closing that is the gating work, ahead of any manifest/publish step.

## Recommendation & readiness order

**Recommendation: do not publish, and do not treat the plugin as tested yet.**
The honest order to reach a *true* "tested / ready" statement:

1. **Fix self-containment** — the 47 broken `framework/…` references. In-repo,
   safe. *(Agent — P1.)*
2. **Add the deterministic validation gate** — manifest + component frontmatter +
   bundled-reference resolution. *(Agent — P1.)*
3. **Live run + install smoke test** — install the plugin via the Claude Code
   CLI, run the skills against a seed requirement, and `claude plugin validate`.
   *(User — P2; cannot run from the dev sandbox, which has no Claude Code CLI and
   does not load the plugin's skills as executable.)*

**"tested / ready" becomes true only after step 3.** Steps 1–2 make the plugin
*installable and statically validated* — they do **not** prove the skills behave
when an LLM runs them. Publishing (the marketplace mirror + submission) follows
step 3. The agent can do **(1) and (2) now**; **(3) needs the user's CLI**.

## Scope

**In — Phase 1 (monorepo, no external dependencies):**

- **Self-containment** — vendor the framework spec the plugin consumes into the
  plugin, repoint references, add a sync script + drift guard.
- **`plugin.json`** — add `author` (+ `$schema`).
- **README** — marketplace install + a usage quickstart.
- **Deterministic validation gate** — a conformance test that fails CI if the
  manifest, component frontmatter, or bundled references regress.
- **Decision record** — the vendoring exception to D-0013.

**In — Phase 2 (when org/domain are registered):**

- **Public mirror repo** — a one-way, generated mirror of the plugin (+ its
  bundle) carrying `.claude-plugin/marketplace.json`; a release/sync workflow.
- **Identity** — org-owned namespace, role email, MIT plugin, product homepage.
- **Live validation** — `claude plugin validate`, a live skill run, an install
  smoke test (Claude Code CLI — a user step; cannot run from the dev sandbox).
- **Submission** — submit to the community marketplace.

**Out:** proving an LLM *running* the skills produces gate-passing docs beyond the
emulated walkthrough (that is the P2 live run); any change to Hermes or the
framework spec (none required); changing the plugin's `name` (`aidoc-flow` is
fine — kebab, non-reserved).

## Approach

### A. Self-containment (the crux)

1. **Vendor the spec subtrees** the plugin consumes —
   `framework/{layers, governance, registry}` → `platforms/claude-code-plugin/framework/{…}`,
   **byte-identical**, generated by a sync script that extends the existing
   `tools/sdd_doc_lint/sync-vendored.sh` pattern (canonical → vendored copy).
2. **Repoint references** in **every plugin file that cites `framework/…`** —
   skills, agents, **commands, `docs/`, and `README.md`** (the current 64-file
   count is skills+agents+commands only; re-scan the full plugin tree, excluding
   the vendored bundle itself). Rewrite `framework/<path>` →
   `${CLAUDE_PLUGIN_ROOT}/framework/<path>` — the documented way for an installed
   plugin to reference its own cached files. *Clarification:* the literal
   `framework/…` form only ever resolved from the monorepo root, **never** in an
   installed copy; `${CLAUDE_PLUGIN_ROOT}` is the runtime anchor and the bundle
   sits at the plugin root in both the monorepo and the cache, so one form is
   correct for the only context where skills execute (installed). Repo-root
   `framework/` and the dev tooling that reads it are unaffected.
3. **Drift guard** — a conformance test mirroring
   `test_doc_lint_vendoring.py`: assert the vendored `framework/` bundle is
   byte-identical to the canonical `framework/{layers,governance,registry}`
   (walk the whole subtree, compare every file). CI fails if a framework edit
   isn't re-synced.
4. **Decision (new D-entry):** vendoring-with-drift-guard is the sanctioned
   *shippability* exception to D-0013 — the monorepo `framework/` stays the
   single source of truth; the plugin's `framework/` is **generated, never
   hand-edited** (identical rationale to the already-vendored `sdd_doc_lint`).
5. **Vendored-doc internal references.** The bundled framework docs are
   byte-identical copies, so their *own* internal cross-references keep
   monorepo-relative form and are **not** repointed (editing them would break the
   drift guard). Treat those intra-doc "see also" links as **advisory** — Claude
   reads sibling bundled files by name regardless; the resolution gate (D)
   enforces only the *plugin's* refs (skills/agents/commands/docs), not the links
   inside vendored docs. If a bundled doc *hard-depends* on a framework file
   outside `{layers,governance,registry}`, add that file to the vendored set
   rather than repoint it.

### B. Manifest

- `plugin.json`: add `author` (`{name}`; email per the identity decision) and
  `$schema: https://schema.claude.com/plugin.json`. Keep `name: aidoc-flow`.

### C. Documentation

- Rewrite the plugin `README.md` to lead with **install** (`/plugin marketplace
  add …`, `/plugin install aidoc-flow@…`) + a **quickstart** (scaffold → drive a
  layer → audit) + a link to `examples/url-shortener/` and `docs/`.

### D. Deterministic validation gate

- `tests/conformance/platforms/test_plugin_manifest.py`:
  - `plugin.json` is valid JSON with required fields (`name` kebab-case,
    `description`); recommended fields present (`version`, `author`, `license`).
  - Every `skills/*/SKILL.md` has a `description`; every `agents/*.md` has
    `name` + `description`.
  - `hooks/hooks.json` is valid JSON with a `hooks` object.
  - **Bundled-reference resolution:** every `${CLAUDE_PLUGIN_ROOT}/framework/…`
    path referenced by a skill/agent exists in the vendored bundle (this is the
    test that would have caught the 47 broken refs).
  - (P2) when `marketplace.json` exists: valid, required fields, no `..` in any
    `plugins[].source`.

### E. Phase 2 — mirror & publish (deferred until org/domain ready)

- Create the public repo (e.g. `aidoc-flow-plugin` under a GitHub **org**) as a
  **one-way generated mirror** of `platforms/claude-code-plugin/` (+ the bundle),
  carrying `.claude-plugin/marketplace.json` (`owner.name` = org/product,
  `source: .`). A release workflow pushes the mirror on a plugin version bump.
- Keep the plugin **MIT** (adoption) and license Hermes / any paid tier
  separately (open-core). `homepage` → a domain you control.
- The user runs `claude plugin validate`, a live skill run, and an install smoke
  test, then submits.

## Step sequence

1. **Decision** — record the vendoring exception in `plans/DECISIONS.md`.
2. **Sync script** — extend the vendoring script to copy the spec subtrees;
   generate the bundle.
3. **Repoint** — rewrite every `framework/…` reference across the **full plugin
   tree** (skills, agents, commands, docs, README) to `${CLAUDE_PLUGIN_ROOT}/framework/…`.
4. **Drift guard + validation gate** — add the two conformance tests.
5. **Manifest + README** — `plugin.json` fields; rewrite README.
6. **Wire the re-sync** — add the framework-bundle sync to the GATE-SPEC /
   spec-change checklist so a future `framework/` edit re-syncs the plugin bundle
   (the drift guard then never surprises CI). The bundle is a snapshot pinned to
   the plugin's `FRAMEWORK_SPEC_VERSION`.
7. **Verify** (below).
8. **Land** P1 — bump the plugin `VERSION` + `plugin.json` `version`; update the
   plugin CHANGELOG + HANDOFF. (P2 later.)

- `test_plugin_manifest` green; full conformance green; markdownlint + ruff clean.

  produces a gate-passing artifact; `/plugin install` smoke test works.

## Risks

| # | Risk | Mitigation |
|---|------|------------|
| R1 | Vendoring contradicts D-0013 (single source of truth) | Drift-guard + decision record; monorepo `framework/` stays canonical; bundle is generated. Precedent: `sdd_doc_lint`. |
| R2 | `${CLAUDE_PLUGIN_ROOT}` may not expand inside SKILL.md *prose* (vs hooks) | It is the documented mechanism for plugin file refs; confirm in the P2 live run. The bundle ships regardless, so worst case is adjusting the reference form, not re-bundling. |
| R3 | 64-file repoint introduces mechanical errors | Scripted (sed) + the bundled-reference-resolution gate catches any dangling/typo ref. |
| R4 | `plm_lint` flags content in the vendored framework docs | Run after vendoring; the framework docs are already legacy-clean, but handle any teaching-example/`Layer` hits (extend exceptions or adjust). |
| R5 | Bundle inflates plugin size / duplicates the spec | Vendor only the consumed subtrees; it is generated, not maintained by hand. |
| R6 | Identity/commercial not finalized blocks P1 | P1 uses a neutral placeholder `author`/owner; P2 finalizes org/domain/email — P1 doesn't depend on them. |
| R7 | "Self-contained + validated" is read as "tested" | The plan is explicit: P1 = static/structural + installable; the **live run + install smoke (P2, user CLI)** is what makes "tested" true. |
| R8 | Vendored docs' own internal cross-refs dangle in the bundle | Accept as advisory (non-blocking "see also"); the resolution gate enforces only the plugin's refs; add any hard-dependency target to the vendored set (Approach A.5). |
| R9 | A future `framework/` edit isn't re-synced → drift-guard CI fails unexpectedly | Wire the bundle re-sync into the GATE-SPEC / spec-change checklist (Step 6); the drift guard is the backstop, not a surprise. |
| R10 | Agent `tools` frontmatter form (comma-string vs array) or thin skill descriptions slip the gate | Gate checks presence; verify the accepted `tools` form against the docs during impl; description *quality* stays the LLM-audit's judgment (a manual check, not deterministic). |

### Pass 1 — 2026-05-27

- **Self-containment is the real gate, not the manifest.** First framing led with
  `marketplace.json`; the audit showed 47 refs / 64 files break on install.
  Reordered so vendoring + repoint + the resolution gate come first; the manifest
  is secondary (R-relates to Objective).
- **Reuse the proven pattern.** Rather than invent a bundling scheme, extend the
  existing `sdd_doc_lint` sync-script + drift-guard precedent and record the same
  D-0013 exception (R1).
- **The resolution gate is the safety net.** Added a conformance check that every
  `${CLAUDE_PLUGIN_ROOT}/framework/…` ref resolves to a bundled file — this is the
  check that would have caught the original breakage and guards the 64-file
  repoint (R3).
- **Don't overclaim "tested".** Split static/installable (P1, in-repo) from the
  live run + install smoke (P2, user CLI); R7 + Scope/Out state this plainly.

### Pass 2 — 2026-05-27

- **Phasing avoids a branding block.** P1 is fully in-monorepo and needs no
  org/domain; identity finalization + the public mirror + submission are P2. P1
  uses placeholders (R6).
- **Conformance interactions checked.** Framework hygiene (`test_spec_hygiene`)

### Pass 3 — 2026-05-27 (gap review)

- **Repoint scope was too narrow.** "64 files" was skills+agents+commands only;

- **Reference form dev-vs-installed.** Clarified that `${CLAUDE_PLUGIN_ROOT}/…` is

- **Land step missing the version bump.** P1 now bumps the plugin `VERSION` +

- **Minor gate items.** Resolution check handles directory refs; verify the agent
  `tools` frontmatter form; description *quality* is a manual (non-deterministic)
  check (R10).
- No further findings — implementable.
